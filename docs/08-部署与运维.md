## 环境拓扑

- `local`：Windows 脚本以 SQLite 开发库运行 API/保留维护/告警；可选 Docker Compose 使用 PostgreSQL、独立 export worker/symbolizer/alerts。OTLP 可指向 mock 或独立 SigNoz，默认本地脚本关闭导出，symbolizer 默认关闭。
- `staging`：与生产同版本、缩小容量，使用独立凭据/数据库/SigNoz，接收合成或允许的测试应用数据。
- `production`：至少两个 Gateway 实例跨故障域；worker 独立伸缩；托管 PostgreSQL HA/PITR；SigNoz/ClickHouse 按官方生产拓扑。

生产入口经 WAF/LB/TLS 到 Gateway。PostgreSQL、OTLP、管理 API、对象存储 endpoint 不公开。数据库迁移是独立 release job，先扩展兼容 schema，再发布兼容代码，最后收缩旧字段。

## 配置与密钥

配置来自环境变量/secret manager，启动时严格校验。最少包括数据库 DSN、OTLP endpoint/TLS、body/批次限制、lease/retry、retention、审计、日志级别、installation HMAC key ring/active version、独立 query cursor HMAC key，以及独立 Web session HMAC key/Secure Cookie。示例 `.env.example` 只能包含占位值；`{}`/空值会让 installation-bearing ingest、cursor pagination 或 Web login fail closed，不能用于生产。

`APM_INSTALLATION_HMAC_KEYS_JSON` 是最多 16 个版本的 Base64 secret map，每个 secret 至少 32 random bytes；`APM_INSTALLATION_HMAC_ACTIVE_KEY_VERSION` 必须命中该 map。`APM_QUERY_CURSOR_HMAC_KEY_B64` 是用途隔离的另一条至少 32-byte Base64 key，不能与 ingest、CI、query credential 或 installation key 复用。轮换前先保留所有仍可能重放/查询的旧 installation key version；cursor key 轮换会主动使旧 cursor 失效，客户端应从第一页重查。

`APM_WEB_SESSION_HMAC_KEY_B64` 是第三条用途隔离的至少 32-byte Base64 key。轮换会主动结束现有浏览器会话；Query key 撤销无需等待轮换，每次请求都会回查。生产 `APM_WEB_SESSION_COOKIE_SECURE=true`，TLS 代理不得把外部 HTTPS 误报为 HTTP。Web HTML/no-store 与 hashed assets 由 Gateway 同源提供，私有 artifact 卷不会挂到静态路径。

符号制品卷挂载到 `/var/lib/androidapm/artifacts`，Gateway 与 symbolizer 共享，不能由静态 Web server 公开。`APM_SYMBOLIZATION_ENABLED=true` 前必须把固定 R8 retrace 与 llvm-symbolizer 放入专用受扫描镜像，使用 JSON argv 环境变量配置绝对命令，并设置实际工具版本。当前基础镜像只包含 Python 实现与 ELF parser，不在构建/启动时下载可变工具。

符号化默认单次工具 timeout 30 秒、lease 120 秒、每轮最多执行 20 个任务；任务逐个领取，整项处理受 lease 前 5 秒的截止时间保护，配置要求 `APM_SYMBOLIZER_TIMEOUT_SECONDS + 5 < APM_SYMBOLIZER_LEASE_SECONDS`。缺制品每 60 秒轮询不消耗工具重试，直接子进程在超时/取消时终止并回收。符号化与导出每次领取都产生新的 owner token，写回按 PostgreSQL 实时时钟拒绝过期租约；慢任务失去租约后允许重放，不承诺下游 exactly-once。详见 ADR 0005。

## 发布流程

1. 锁文件、测试、迁移 dry-run、镜像扫描、SBOM。
2. 构建一次并以 immutable digest 推广，禁止环境间重建。
3. staging 迁移、部署、回放契约 fixture、SigNoz 查询和告警冒烟。
4. 生产先迁移，再 canary Gateway/worker，观察 ACK/积压/导出/资源。
5. 分批滚动；异常回滚应用镜像。数据库只使用前向修复迁移。

## 核心运维指标

- `ingest_requests_total{status,protocol}`、`ingest_events_total{result}`、ACK latency。
- auth failure/scope mismatch/quota rejection，标签不得包含 key 或高基数 eventId。
- inbox pending、oldest age、claim rate、retry、dead letter、prune。
- OTLP requests/events/latency/result、映射错误。
- DB pool、transaction latency、unique conflicts、storage/WAL。
- process CPU/RSS/FD/event-loop lag；自身日志含 requestId/tenantId 但不含 payload。
- artifact upload result/bytes/conflict、`symbolization_jobs_total{result,job_type}`、symbolization latency、`awaiting_symbols/symbols_missing/metadata_missing` 水位与最老年龄。

## 备份、恢复与灾备

- PostgreSQL 开启每日全量 + 连续 WAL/PITR；对象存储版本化/生命周期；Dashboard/告警/配置资产在 Git。
- 每季度从备份恢复到隔离环境，校验行数、约束、租户、随机样本和应用启动；记录实际 RPO/RTO。
- SigNoz/ClickHouse 依据业务保留和重建能力备份。inbox 保留窗口内可重放，但不能把它当无限期唯一备份。

## Runbook

- Gateway 5xx：先看 DB/连接池/body limit/最近发布；不通过返回 2xx 隐藏故障。
- Inbox 积压：区分 worker 容量、OTLP 限流、永久 schema 错误；必要时保护性 `503`。
- Duplicate 飙升：检查客户端网络/ACK 丢失，不删除唯一约束。
- Dead letter：按错误码聚合，修复 mapper/凭据后走审计重放。
- 磁盘水位：停止非必要导出/保留任务，保护 WAL/inbox；禁止无审计删除 pending。
- 密钥泄漏/跨租户：立即撤销和隔离，保存证据并按安全响应流程处理。

## 备份与恢复演练清单（截至 2026-11-07 尚未执行）

仓库目前没有 `pg_dump` / PITR 自动化脚本，也没有任何恢复演练证据。以下是在服务器上执行并留存证据的最小闭环；执行前不得把上文"每日全量 + 连续 WAL/PITR"记为完成。命令中的容器名以 `docker ps` 实际结果为准，云端项目名与仓库 compose 不同。

1. **每日全量**（容器内、独立备份目录，避免写入系统盘同一分区后无空间可恢复）：
   `docker compose exec -T postgres pg_dump -U androidapm -Fc androidapm > /var/backups/androidapm-$(date -u +%Y%m%dT%H%M%SZ).dump`
   随后 `pg_restore -l <dump>` 校验可读、`sha256sum` 记录哈希、按保留期清理旧文件，并上传到与实例地域匹配的独立存储（COS 套餐包的地域必须先核对，不能假定覆盖首尔）。
2. **WAL / PITR**：单机 compose 默认没有 `archive_command` 或基础备份链路，不能声称具备 PITR；需切换到托管 PostgreSQL 或显式配置 WAL 归档并验证时间线恢复。
3. **季度恢复演练**：在隔离实例创建空库，执行 `pg_restore -d androidapm_restore <dump>`，核对 `alembic version` head、`inbox_events` 各状态行数、审计表与告警/规则表，再从恢复库跑一次只读 Smoke；禁止直接覆盖生产库。
4. **证据留档**：命令、UTC 时间、dump 哈希与大小、恢复耗时、校验结果、失败项与修复记录。演练库的合成数据不是生产验收证据。
5. **容量联动**：60 GB 单盘与默认 `APM_INBOX_MAX_RAW_BYTES=10 GiB` / 100000 事件 / 7+30 天保留存在张力；容量准入只限制 inbox 行数和 raw 字节，不检查磁盘余量。备份前检查 `df -h`、WAL 增长与 dead letter 堆积，外部 OTLP 不可达时优先排查导出链路而不是删除 pending。

资源限制同理：仓库 `compose.yaml` / `compose.production.yaml` 刻意不写死 `mem_limit`，因为 2C4G 云端的实际上限来自服务器侧 override；回收该 override 前不要在仓库里猜一个数值。

# 2026-09-07 运行指标

Gateway `/metrics` 在 3 秒时限内读数据库；独立 worker 进程每 15 秒刷新快照，并分别在 9101/9102 提供自身的进程计数器。`APM_METRICS_BIND` 默认 127.0.0.1，Compose 设为内部网络 0.0.0.0 且不映射宿主端口；Caddy 明确拒绝公网 `/metrics`。采集配置见 `deploy/prometheus-scrape.yaml`。

`androidapm_inbox_rows{status}` 展示固定状态的行数；`inbox_pending` 仅计已到期 pending 和已过期 processing，最老年龄来自这些可领事件。数据库失败时 snapshot_available=0、相关值为 NaN，最近成功 timestamp 保留用于判断过期，不能把失败视为空队列。监控应同时检查抓取 up、快照 availability/timestamp 和 worker_cycle_timestamp。多个 target 的 backlog 是同一数据库快照，不可相加；export/symbolizer 的进程计数器必须从对应 target 采集。独立子进程 HTTP 指标回归已验证；尚未在 Docker/SigNoz 实际网络中采集。
# 2026-09-07 保留与容量准入

export worker 每 `APM_RETENTION_INTERVAL_SECONDS=60` 秒执行最多 `APM_RETENTION_BATCH_SIZE=1000` 行的清理；`APM_RETENTION_ENABLED=false` 可关闭。delivered 从 finalized_at/delivered_at 起保留 7 天，dead_letter 从 finalized_at 起保留 30 天；旧行回退 next_attempt_at。仅清理终态、没有未完成符号任务的行，待交付/等待符号/活跃租约不会被策略删除。清理 payload、堆栈、Native 身份和符号输出，只保留 module/name、数值投影及去重/发生时身份元数据。raw read 在审计后返回 410；旧批次重放依旧按原 hash/HMAC key version 判断。quota 窗口超过 24 小时才删除，清理动作与计数审计同事务提交，清理失败不会阻塞导出循环。

`APM_INBOX_MAX_LIVE_EVENTS=100000` 与 `APM_INBOX_MAX_RAW_BYTES=10737418240` 控制未完成事件量和保留的 canonical raw payload 字节量。新批次在 ACK 前检查，PostgreSQL 事务级 advisory lock 串行化容量准入；超限整批回滚，503 + Retry-After: 30，重复-only replay 可继续 ACK。原始字节限制不包括索引/WAL/符号制品/去重元数据，并不等于文件系统硬配额；需根据实际 PostgreSQL 存储和入口吞吐配置。去重元数据长期保留，完整主体删除需显式生命周期策略。新增迁移回填既有 payload 大小，会扫描 inbox；生产须安排迁移窗口。详见 ADR 0008。
