# 符号化、构建制品与远程配置

## 构建标识

事件 envelope 最终需要：`appId,environment,appVersion,appBuild,variant,versionCode,sdkVersion`；Java 使用 `fields.stackTrace`，Native 另需 `fields.abi,fields.buildId,fields.backtrace`，backtrace 至少包含模块相对 `pc`。没有完整事件身份时状态为 `metadata_missing` 并导出 raw；身份完整但制品未上传时状态为 `symbols_missing` 并进入待制品队列，不能选择“最接近”的制品产生错误结果。

### 当前协议约束

V2 仍从请求 Header/batch resource 获得 `versionCode/appBuild/variant/serviceVersion`，只能标为 `REQUEST_DECLARED/BATCH_DECLARED`。V3 已把 serviceVersion/versionCode/appBuild/variant/installation 和可选 Native frames 写入 durable event occurrence，服务端持久化为 `OCCURRENCE_BOUND`；应用升级后上传旧 V3 outbox 行不会改写发生版本。

当前精确符号化边界为：

- production symbolizer 保持默认关闭；V2/请求级 build metadata 只用于受控同构建 fixture/staging，不作为真实历史 outbox 的精确匹配依据。
- normalization 将 `REQUEST_DECLARED/BATCH_DECLARED` 与 V3 `OCCURRENCE_BOUND` 分开；前两者即使字段齐全，也按 `metadata_missing` 原因 `OCCURRENCE_IDENTITY_NOT_PROVIDED` 走 raw-only。
- V3 schema/durable codec 已支持 Native ABI、module build-id/name、relative PC/load bias；真实 Native crash 模块、每 ABI 制品与工具仍要证明会填充并正确消费这些字段。
- 服务端仍用 authenticated tenant/app/environment 约束制品选择；客户端快照不能改变 credential scope。eventId 重放若携带不同 occurrence snapshot 必须 `409 event_id_conflict`。

具体 wire 规则见 `docs/02-SDK-Collector协议.md`。协议与本地闭环已关闭；生产精确符号化仍被真实采集 coverage、固定 R8/LLVM 镜像、对象存储/KMS 和真实 crash fixture 阻塞，不能用“Header 与当前 APK 一致”的烟测替代。

## 制品上传

管理入口使用 CI 身份，不复用 ingest key：

```text
POST /v1/artifacts/java-mapping
POST /v1/artifacts/native-elf
```

上传使用独立 `apmci1_...` CI Bearer key 和 `artifact:write` scope，绝不复用 APK ingest key。共同 header 为 `X-APM-App-Id/X-APM-Version-Code/X-APM-App-Build/X-APM-Variant/X-APM-Checksum-SHA256`；Native 再要求 `X-APM-ABI/X-APM-Build-Id`。

Gateway 有界流式写入私有 staging 文件并同步计算 SHA-256。Java mapping 必须是 UTF-8 且包含 R8/ProGuard class mapping；Native 当前只接收未剥离 ELF，使用 pyelftools 验证支持的机器架构、`.symtab` 与 GNU build-id。验证后在同卷原子 `replace` 到内容寻址键，数据库以 tenant/type/app/versionCode/appBuild/variant/ABI/build-id 建立唯一身份。相同 identity + checksum 幂等成功；相同 identity + 不同 checksum 返回 `409` 并审计。当前 store 是本地/持久卷 adapter；生产 S3 兼容对象存储、KMS、签名下载与清理 reconciliation 尚待实现。

## Java 符号化

- 按 tenant/app/versionCode/appBuild/variant 精确匹配 `mapping.txt`。
- 使用固定版本 R8 retrace，保存工具版本、输入哈希、mapping 哈希和输出。命令通过 JSON argv 配置并直接执行，不经过 shell。
- 指纹基于符号化后稳定栈帧，同时保留原混淆堆栈。2026-09-12 起成功的 Java 符号化事务同步更新 Issue 指纹，原始指纹保存在 `raw_incident_fingerprint`；迁移 `20260912_0007` 对历史完成任务执行同样转换。旧链接按 scope/window 解析，歧义返回 409，详见 ADR 0009；已导出外部 SigNoz 的历史记录不自动回写。

## Native 符号化

- CI 上传每 ABI 的未剥离 ELF 或符号包，并提取/验证 GNU build-id。
- tombstone/minidump 的模块 build-id 是匹配权威；ASLR 地址先按 load bias 归一。
- 使用固定 NDK/llvm-symbolizer 工具链版本；当前 adapter 从 Android backtrace 读取模块相对 `pc` 并保存工具版本、输出和指纹。完整 tombstone 多模块/load-bias 解析和 Breakpad/Crashpad minidump 尚待实现。
- 错误或缺失 build-id 必须显式失败并进入待制品队列。

## 当前任务状态机

- symbolizer 启用时，ingest 事务为元数据完整的 Crash 创建唯一 durable job，并把 inbox 置为 `awaiting_symbols`；关闭时记录 `disabled` 并继续 raw export。
- symbolizer 使用 `FOR UPDATE SKIP LOCKED`、owner/lease/expiry、指数退避；每次只在即将执行时领取一个任务，`APM_SYMBOLIZER_BATCH_SIZE` 仅限制每轮处理数，不预占后续任务的租约。每次领取使用新的 owner token，同一进程重领也不能接受旧结果。
- 制品查询、工具执行和完成提交共享单任务截止时间，截止点为 lease 前 5 秒；工具 timeout 必须比 lease 短超过 5 秒。超时或取消会终止并回收直接启动的工具进程。任务不通过续租无限延长，未完成任务由租约过期重领恢复。
- 开始工具尝试、完成、失败和缺制品挂起均校验 owner/status/未过期租约；PostgreSQL 以 `clock_timestamp()` 判定，避免事务起始时间或 worker 时钟偏差放宽权限。符号化结果与 inbox 放行同事务，结果指标在提交后增加。
- `symbols_missing` 保持等待并每 60 秒重查，不增加 `attempt_count`；找到精确制品后，实际工具尝试前才提交计数。工具预算耗尽后进程崩溃重领也不会额外执行。既有 attempt_count 保留，不能自动推断旧次数属于工具执行还是缺制品轮询。精确匹配制品上传后立即回到 `pending`，避免上传/状态提交竞态造成永久停滞。
- `symbolized` 或工具重试耗尽的 `failed` 释放 raw event 给 OTLP worker；OTLP 属性包含 status、工具版本、指纹和可用的 symbolized stack。
- `androidapm-symbolizer` 默认关闭；基础 Python 镜像没有内置 R8/LLVM。只有部署固定工具二进制并配置已审核版本后才能启用，当前不能宣称真实 Java/Native 样本已经还原。

## 远程配置控制面

配置对象按 tenant/app/environment 定位，包含单调 revision、issuedAt/expiresAt、灰度规则、模块开关、采样率、限流、endpoint、隐私规则版本和 emergency kill switch。发布内容使用离线受保护签名密钥签名；服务端保存不可变版本和审计。

客户端 `apm-remote-config` 已实现有界 HTTPS 拉取、每请求动态凭据、ETag/304、Tink Ed25519 pinned-key 验签、规范 JSON、app-private last-known-good 缓存、revision rollback/equivocation 防护、可信时间/过期、定时刷新、失败回退和 core 动态配置/kill switch 接入。灰度 bucket 由服务端按 tenant rollout salt + installation anonymous ID 稳定计算，客户端只消费签名后有效的配置结果。

仍未完成的是生产端到端运营闭环：真实部署下的 server/client E2E，短期 Token 签发与撤销，public key pin/轮换/泄漏恢复，签名私钥迁移 KMS/HSM，配置 payload schema/兼容矩阵，发布审批与回滚演练，以及配置获取/应用失败的服务端可观测证据。服务端不得把“API 和双方组件已有”描述成远程配置已经生产上线。

服务端实现使用 `GET /v1/config`，凭 ingest credential 解析 tenant/app/environment，并要求 `X-APM-Installation-Id` 只在请求内参与 tenant rollout salt 的稳定 HMAC 分桶，不把该明文写入配置记录。响应由 Ed25519 对规范 JSON 签名，支持 ETag/304；发布通过 `androidapm-admin publish-config` 产生单调 revision 和审计记录。生产签名私钥应迁移到 KMS/HSM；当前环境变量原始私钥仅用于本地/staging。

## API 安全

- 读配置可用短期 app token；发布配置和上传符号只允许 CI/admin 身份。
- 签名私钥不进入 Gateway 容器；在线发布可调用 KMS/HSM。
- 灰度以 tenant salt + installation anonymous ID 稳定分桶，不能用可枚举用户标识。
- kill switch 只关闭 APM 模块，不得执行任意代码或改变宿主业务功能。
