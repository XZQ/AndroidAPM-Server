# 符号化、构建制品与远程配置

## 构建标识

事件 envelope 最终需要：`appId,environment,appVersion,appBuild,variant,versionCode,sdkVersion`；Native 另需 `ABI,build-id,module,pc/load address`。没有精确标识时状态为 `symbols_missing`，不能选择“最接近”的制品产生错误结果。

## 制品上传

管理入口使用 CI 身份，不复用 ingest key：

```text
POST /v1/artifacts/java-mapping
POST /v1/artifacts/native-symbols
```

上传先流式计算 SHA-256、验证大小/格式，再写对象存储临时键；数据库事务登记唯一 build identity 后原子转正。相同 identity + checksum 幂等成功；相同 identity + 不同 checksum 冲突并审计。下载使用短时签名 URL 或 worker 私网身份。

## Java 符号化

- 按 tenant/app/versionCode/appBuild/variant 精确匹配 `mapping.txt`。
- 使用固定版本 R8 retrace，保存工具版本、输入哈希、mapping 哈希和输出。
- 指纹基于符号化后稳定栈帧，同时保留原混淆堆栈。

## Native 符号化

- CI 上传每 ABI 的未剥离 ELF 或符号包，并提取/验证 GNU build-id。
- tombstone/minidump 的模块 build-id 是匹配权威；ASLR 地址先按 load bias 归一。
- 使用固定 NDK/llvm-symbolizer 或 Breakpad/Crashpad 工具链版本；函数、偏移、文件和行号均带置信状态。
- 错误或缺失 build-id 必须显式失败并进入待制品队列。

## 远程配置控制面

配置对象按 tenant/app/environment 定位，包含单调 revision、issuedAt/expiresAt、灰度规则、模块开关、采样率、限流、endpoint、隐私规则版本和 emergency kill switch。发布内容使用离线受保护签名密钥签名；服务端保存不可变版本和审计。

SDK 客户端仍需实现：拉取、签名校验、可信时间策略、本地缓存、过期、失败回退、灰度稳定分桶和紧急关闭。服务端不得把“已有配置 API”描述成端到端远程配置已经完成。

服务端实现使用 `GET /v1/config`，凭 ingest credential 解析 tenant/app/environment，并要求 `X-APM-Installation-Id` 参与 tenant salt 的稳定灰度分桶。响应由 Ed25519 对规范 JSON 签名，支持 ETag/304；发布通过 `androidapm-admin publish-config` 产生单调 revision 和审计记录。生产签名私钥应迁移到 KMS/HSM；当前环境变量原始私钥仅用于本地/staging。

## API 安全

- 读配置可用短期 app token；发布配置和上传符号只允许 CI/admin 身份。
- 签名私钥不进入 Gateway 容器；在线发布可调用 KMS/HSM。
- 灰度以 tenant salt + installation anonymous ID 稳定分桶，不能用可枚举用户标识。
- kill switch 只关闭 APM 模块，不得执行任意代码或改变宿主业务功能。
