## 边界与客户端输入

AndroidAPM 客户端已经负责采集、限流/聚合/脱敏、稳定 `eventId`、SQLite durable outbox、claim/lease/expiry、多进程本地交接、批量上传和独立 SDK 自诊断。云端必须把客户端交付视为“至少一次”：请求完成状态不明确时客户端可能重传，同一 `eventId` 必须安全去重。

客户端可发送 legacy Line Protocol、4-byte length-prefixed Protobuf，或显式 `PROTOBUF_ENVELOPE_V2/V3`。Protobuf `event_id` 为字段 14；durable codec V4 保留该 ID、显式标量类型和 occurrence/native identity，并继续读取 V1/V2/V3。V2 使用字段 15 typed values、batch-declared resource 和 `b2-` 稳定 batch ID；V3 增加字段 16 occurrence identity、`b3-` batch ID，并成为 strict built-in HTTP 的必需协议。两者共享 1 MiB 默认/4 MiB 绝对未压缩请求预算和 schema/batch/count 精确整批 ACK；旧格式不会被静默解释为 V2/V3。

## P0：Collector 与租户安全

当前 `main`（唯一服务端分支）已统一 legacy/V2/V3 Collector：认证 scope、配额、有界 Gzip、12 种 typed scalar、V3 occurrence、installation HMAC、PostgreSQL inbox 模型、`(tenant_id,event_id)` 去重/冲突及提交后精确整批 ACK 位于同一实现线。真实 Android `HttpApmUploader` 已经 Gzip HTTP、运行中的 Gateway 和测试用 SQLite 复核 V2/V3 exact ACK、occurrence、HMAC 与重复重放。完整本地门禁见 `PROJECT_HANDOFF.md`；TLS ingress、Docker/Compose、PostgreSQL commit-uncertainty、代理丢 ACK、生产凭据轮换和部署验收仍未完成，因此本项不能标记为生产完成。

- 建设 TLS Collector ingress，支持批量请求、Gzip、请求体上限、超时和明确的整批 ACK。
- 定义认证方式、密钥轮换、应用/环境/版本身份和撤销流程；密钥不得硬编码在 APK。
- 实现 tenant/app/environment 隔离、写入配额、速率限制、拒绝原因和审计日志。
- 对 `eventId` 建立带保留期的唯一约束或幂等索引；重复请求返回成功 ACK，不重复进入下游。
- 明确部分成功策略。当前客户端按整批成功确认，云端若需要逐条拒绝，必须先扩展版本化 ACK 协议。
- 校验时间戳、枚举、字段大小、字段数量和压缩炸弹；未知字段可前向兼容，非法事件不得污染共享队列。

验收：重放同一批次、并发提交同一 `eventId`、ACK 丢失后重传、跨租户伪造、过载和畸形数据均有自动化测试；任何场景都不能重复落入聚合事实表或越权读取。

## P0：存储、查询、聚合、告警与 Dashboard

截至 2026-10-13，同源诊断 Web 包含总览、Issues/详情、事件探索/详情、版本、数据质量、性能、告警和设置。性能已实现 70 个契约的分位数/趋势/覆盖，告警已实现规则、触发/恢复、确认/静默和持久化重试 outbox，管理面已实现独立 admin、凭据生命周期、签名配置/递增回滚和审计；Android Sample Debug 接入本地 V3。见 [本地功能](11-本地产品功能.md)。OTLP Metrics、标准 session/device/OS、生产 SSO 和真实 SigNoz staging 仍未完成。SigNoz 离线 alert 模板无 channel 且 `production_ready=false`；这与新实现的独立告警服务是两个不同运行路径。

首个产品垂直切片冻结为“新版本 `crash/java_crash` 与 `anr/anr_detected` 可信闭环”：先完成 exact event 口径、版本/安装身份与质量状态，再完成受影响/活跃安装、指纹/详情和告警触发/恢复。`app_exit` 作为历史退出证据单列，未有 incident ID 前不与现场事件相加；客户端无统一 telemetry session 时不计算 Crash-free/ANR-free sessions。

- 设计原始事件、指标时序、Trace/Span、错误指纹和维度字典的数据模型及冷热分层。
- 建设版本化字段注册表、发生/接收时间、raw/aggregated、availability、PII/cardinality 和 legacy/V2/V3 类型与身份语义。
- 用真实跨升级设备 fixture 验收 V3 occurrence-bound release/versionCode/appBuild/variant/installation；Native 再验证 ABI/module build-id/relative PC coverage。V2 batch/request 声明继续不得冒充发生时身份。
- 把现有 HMAC key ring 接入生产 secret manager/KMS，完成轮换、断点、删除和全输出明文扫描；明文不得进入 durable payload、日志、OTLP 或 Dashboard。
- 把已实现的同源 Web/短时 Query session 接入生产 OIDC/SSO，补生产限流/RLS/审计留存；共享多租户仍可选择物理隔离。浏览器继续不得保存长期 `apmq1`。
- 验收已有性能百分位与版本差值，后续按真实产品需求扩展跨版本指纹合并策略和基线异常检测。
- 将已实现的告警规则、静默/恢复、重试与审计接入真实通知渠道；值班路由由通知网关承担。
- 在真实 staging 验收现有健康、Crash/ANR、13 个性能域与 SDK 自健康页面。
- 定义数据保留、删除、导出、地域、隐私主体请求和灾备恢复目标。

验收：真实 Android V3 fixture 关闭生产版本/安装分母、指纹/详情、告警触发/恢复和 Dashboard 门禁；V2/legacy fixture 保留兼容与质量排除断言。所有组都要验证普通 `app_exit` 不污染 Crash、helper event identity 不制造假空数据、缺失不填零，并验证读取租户隔离。

## P1：Native 符号化服务

当前服务端已实现独立 CI key、Java mapping/未剥离 Native ELF 有界上传、SHA-256 与精确 build identity、PostgreSQL durable job、待制品重排队以及固定 argv retrace/llvm-symbolizer adapter；客户端 V3 也已持久化 occurrence release/build/variant 与可选 ABI/build-id/native frame。当前 store 仍是私有持久卷，symbolizer 默认关闭；生产对象存储/KMS、固定工具镜像、真实 Native collector coverage 和 Java/每 ABI 崩溃验收仍未完成。

- 在构建流水线上按 app/version/variant/ABI/build-id 上传未剥离 ELF、mapping、源码映射及校验和。
- Collector 接收 tombstone/minidump 后按 build-id 精确选择符号，不允许仅按版本字符串猜测。
- 后台任务完成 unwind、符号解析、源码行映射、指纹聚合和重试/死信处理。
- 符号文件需要权限、加密、保留期、删除与上传完整性审计。

验收：每个支持 ABI 使用真实崩溃样本验证函数名、偏移和源码行；错误 build-id 必须显式失败，不能产生错误符号结果。

## P1：Maven Central 或企业制品库

- 准备 namespace/账号、PGP 或平台签名、发布凭据和最小权限机器人身份。
- 在隔离流水线执行测试、lint、Release、签名、staging、校验、promotion 和失败回滚。
- 校验 POM、sources、AAR/JAR、签名、checksums、依赖图和版本不可变性。
- 从全新 consumer 工程仅通过外部仓库解析并构建，不得回落 Maven Local。

验收：一个正式版本完成 staging 到 release，外部 consumer 在空缓存环境解析成功，制品哈希和签名可复核。

## P1：云端 CI 与分支保护

- 两个仓库已有 CI 配置；本轮本地产品变更仍需对应提交在真实 workflow 重新验证，不能沿用旧提交的绿色状态。
- 必需检查应选择 JDK 17（Gradle 可在兼容的更高 JDK 上运行但字节码仍为 Java 17），覆盖 API/ABI 兼容、单测、Debug/Release、lint、插件测试、Maven Local 发布、隔离 consumer 和文档校验。
- 服务端 `main`、客户端 `develop` 分别设置保护规则、最小评审、禁止强推、必需状态检查和发布 tag 权限。
- 密钥只进入受保护环境；Fork/不受信任 PR 不获得发布凭据。

验收：干净 runner 可复现本地验证链；失败检查阻止合并，发布 job 只能由受保护 tag/环境触发。

## P2：真机设备实验室与长稳基线

仓库内 `apm-benchmark` 已提供可编译的 AndroidX Microbenchmark，用于 codec 和 SQLite outbox 热路径。以下结果必须在真实设备产生，不能用本地构建成功代替：

截至 2026-07-25，Redmi/Xiaomi `22041216UC` 已在允许 USB 安装后完成真实 AndroidX microbenchmark，三项 checked-in budget 均通过；FPS 静态页面 CPU 问题修复后，两次原预算 smoke 通过，CPU 为 `12.928%` / `12.362%`。OnePlus `PLK110` Android 16 也完成 schema-v2 smoke，覆盖 OEM 禁止 `pm clear` 时的 uninstall/reinstall fallback，并取得可校验 UID power evidence；后续 smoke 还验证了有界只读 ADB 重试的正常路径。首个 OnePlus 24h 因设备离线超过当时重连窗口而无结果，Redmi 长跑随后按项目决定主动取消；没有 24h/72h 通过结论，长稳执行明确延期到发布前的受管设备实验室或校准电源设施。模拟器结果仍不进入物理性能基线。

- Android 7/8、10/11、13/14 及当前版本；arm64 为主，保留实际业务需要的 32 位覆盖。
- 至少覆盖 Google/AOSP、Samsung、Xiaomi、OPPO/OnePlus、vivo 等目标 OEM。
- 24h/72h soak：前后台切换、网络断续、进程杀死、重启、磁盘压力、多进程事件和上传 lease 过期。
- A/B 测量 SDK 关闭/开启后的启动、主线程帧、CPU、PSS/Heap、线程、唤醒、网络字节和磁盘增长。
- 固定设备型号、系统 build fingerprint、电量、充电状态、温度/thermal state、亮度、网络、应用版本和场景脚本。
- 保存原始 AndroidX JSON/trace、Perfetto/Battery Historian 或等价原始证据、日志、APK 哈希和统计脚本版本。

验收：先定义每项预算和置信区间，再执行重复实验；报告至少给出 median/P90/P99、样本数、方差、热降频/失败样本和原始证据链接。没有设备结果时只写“待执行”，不得写推测数值。

## 推荐建设顺序

1. 把已统一的 V2/V3 Collector + 认证/租户 + `eventId` 去重 + 精确整批 ACK 部署到 PostgreSQL/TLS staging，并完成并发、ACK 丢失和故障注入验收。
2. 在同一 staging 验收已实现的 V3 occurrence/HMAC/首批注册表/Query/BFF，并完成生产 key/RLS/读取隔离与跨升级 fixture。
3. 把已实现的新版本 Java Crash/ANR 页面部署到同源 HTTPS staging，完成真实 SigNoz、告警触发/恢复、通知、SSO 和发布决策操作验收。
4. 在同一注册表上扩展启动/帧/网络，再完成 Native 符号上传和后台符号化。
5. 完成外部制品发布与受保护云端 CI。
6. 持续运行设备矩阵，把 benchmark/soak 结果变成版本门禁。
