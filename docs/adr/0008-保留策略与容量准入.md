# ADR 0008：原始证据保留与事务容量准入

日期：2026-09-07。状态：已实现，本机 SQLite 验证；未执行生产清理。

## 决策

既有 7 天 delivered / 30 天 dead-letter 配置由 export worker 定期执行。一次最多处理配置的行数，PostgreSQL 通过行锁和 skip locked 允许多 worker 协作；只处理 inbox 终态且没有 pending/processing/symbols_missing 作业的事件。清理不可恢复的 raw/堆栈/Native/符号结果，写 raw_pruned_at；保留原始 payload hash、tenant/event 唯一键、发生时 release、安装 HMAC/key version 及必要数值事实。不删除 inbox 行，因此迟到重放不会重新导出，也不允许不同内容覆盖历史身份。原始证据接口必须先记录 expired 审计，再返回 410，不能将保留的摘要冒充原始 payload。

容量以 live inbox 行数和未清理 canonical raw 字节数控制。新 batch 入库事务在 ACK 前通过 PostgreSQL transaction advisory lock 串行准入；超限回滚包含 quota 在内的整个事务，返回可重试的 503。重复-only 请求不增加原始数据，继续按原 key version ACK。SQLite 仅用于兼容与功能回归，不代替 PostgreSQL 多进程并发证明。

## 影响与边界

原始证据清理不减少已观察到的事件计数，但字符串场景等已过期证据变为不可用。去重元数据会继续增长；物理磁盘/WAL/索引和独立符号制品的配额需运维监控，逻辑 raw 上限不宣称磁盘硬保证。回退 schema 不恢复已清理数据。容量统计查询与迁移回填需在真实 PostgreSQL 数据规模上评估；未完成作业不因磁盘压力被偷偷丢弃。后续主体删除或去重时间窗变更必须单独决策。

## 2026-09-12：证据状态补充

场景原值仍按原 TTL 清理。清理前仅将是否有非空场景写为 normalized `retention.scene_state=EXPIRED/MISSING`；无此标记的历史清理行按 `RETENTION_UNKNOWN` 查询，不推断客户端未提供。保留的事件权重参与分布覆盖计数，部分证据不可用时显示降级，不把剩余场景当成完整分布。

注册字段原 AVAILABLE 且清理后不在 `registered_fields` 中时变为 EXPIRED，包含旧清理行的查询兼容路径。INVALID/MISSING 与保留的数值 AVAILABLE 状态不变。没有新表或迁移，不执行外部历史数据恢复。SQLite 实际清理前后回归证明事件计数、安装计数、数值事实、重放保护与过期语义；生产清理和 PostgreSQL 并发仍需独立验收。
