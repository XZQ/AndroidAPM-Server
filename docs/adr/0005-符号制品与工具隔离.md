# ADR 0005：符号制品身份与工具进程隔离

- 状态：Accepted
- 日期：2026-07-16

## 决策

APK ingest key 与构建 CI key 分离；制品以 tenant/type/app/versionCode/appBuild/variant/ABI/build-id 为不可变唯一身份，并同时校验服务端 SHA-256。Native 第一版只接受带 `.symtab` 和 GNU build-id 的未剥离 ELF。

Crash 符号化使用 PostgreSQL owner/lease/expiry job，不在 Gateway 请求线程执行。R8 retrace 与 llvm-symbolizer 通过固定 JSON argv 直接启动，不经过 shell；工具二进制和版本由部署镜像提供，基础应用镜像不在启动时下载。

## 原因

构建制品属于高权限供应链输入，不能复用可分发到 APK 的写入凭据。精确 build identity 和 checksum 冲突可阻止错误符号静默污染指纹。外部工具隔离让超时、退出码、输出上限和版本证据可审计，也避免把复杂解析器重写成不完整的 Python 实现。

## 后果

没有完整客户端 build 元数据时只能标记 `metadata_missing`；没有精确制品时进入 `symbols_missing`，不得按版本猜测。生产启用前必须构建固定 R8/LLVM 工具镜像、接入私有对象存储/KMS，并用真实 Java/每 ABI Native crash fixture 验收。
