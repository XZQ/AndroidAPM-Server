# ADR 0010：本地性能查询、告警生命周期和管理权限

日期：2026-10-13。状态：accepted。

现有 Crash/ANR Query/BFF 已提供同源、固定 scope 和可撤销会话，性能、告警、设置需要在没有生产服务器的情况下成为可操作功能。

性能采用源码复核的精确 module/name/field 目录，Normalization v3 注册 70 个数值观测。查询在 SQL 中先限定 tenant/app/environment、发生窗口、版本和性能事件，再读取不超过 `APM_QUERY_MAX_ROWS` 的投影。超限拒绝整个结果；不返回部分分位数。P50/P75/P95 使用线性插值，统计对象是上报观测，不能用窗口平均值推断单帧或单请求分布。只比较 OCCURRENCE_BOUND 版本；缺失、无效、不可用、空窗口与真实零分别呈现。GC availability=false 的占位值不进入分布。历史 retained raw 可通过有界 backfill 重建投影，已过期证据不补造。

告警由独立 `androidapm-alerts` 进程评估，不依赖 SigNoz 或 OTLP 导出成功。规则、实例和通知 outbox 使用数据库持久化；同一 tenant 的事务更新锁串行化评估和管理写入。每次 firing episode 只有一个实例，触发和恢复各创建一次通知。空遥测窗口、低样本和缺失指标不能自动恢复现有实例。计数规则衡量已报告的精确事件，而非未观测的总体事故率。暂停保留实例和历史，恢复启用后重新评估；活动实例只允许切换启用状态，不能修改指标语义。

Webhook 目的地及鉴权头由服务器 `APM_NOTIFICATION_CHANNELS_JSON` 预配置，Web 只选择 alias；不提供任意 URL 写接口。投递使用唯一 owner、数据库时钟到期 fencing、有界尝试与退避、禁止重定向、不读取响应体、稳定 Idempotency-Key。语义是至少一次，接收方负责幂等；静默只抑制通知，转换仍记录为 SUPPRESSED。没有渠道时规则仍可用于本地控制台。

新增独立 `admin` Query 角色。viewer 保持 L0，investigator 保持 L1/L2 与发布决策权限；admin 在相同不可变 scope 内额外拥有告警管理、应用名称、Query/Ingest/CI 密钥生命周期和签名配置发布/回滚。CLI 是首个 admin 的 bootstrap 入口，旧凭据不自动提权。Web 所有写操作都要求绑定 CSRF；管理操作审计不保存密钥或配置正文。新 secret 仅在提交成功后的响应出现一次，不持久化到浏览器。回滚配置发布递增的新 revision，避免客户端 rollback floor 拒绝。

本地启动同时管理 API、告警、保留维护三个进程；SQLite 明确仅用于开发。生产仍使用 PostgreSQL，需要现场并发/故障验证。SSO、标准 telemetry session/device/OS、原生 Trace/OTLP Metrics 和真实设备采集 coverage 不从当前字段推断，也不以本地验收代替生产接受。

## 2026-11-02 崩溃后重试与租约补充

通知 claim 前把已用尽尝试且无活跃租约的 outbox 行置为 FAILED/RETRY_EXHAUSTED，不再发请求；最后一次活跃 owner 仍可完成。领取、到期和最终写回使用与导出 worker 相同的数据库实时时钟 helper，避免 PostgreSQL 事务开始时刻在锁等待后放宽过期 owner。重试计划与 Idempotency-Key 不变。
