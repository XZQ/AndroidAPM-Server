# ADR 0007：同源 Web 控制台与短时 Query 会话

- 状态：Accepted / Implemented
- 日期：2026-08-28

## 背景

首个 Crash/ANR 产品切片已有 fixed-scope Query/BFF，但没有托管网页。直接让 React 保存长期 `apmq1` 会扩大 XSS、浏览器同步、扩展、截图和共享设备风险；另建脱离 Server 的静态站点又会引入 CORS、跨域 Cookie、第二套部署和绕过现有租户边界的可能。

当前没有可接入的企业 SSO/IdP。为了先完成本地可用页面，同时不给未来 SSO 制造错误边界，需要一种不把长期 Query secret 持久化到浏览器、可被服务端撤销、可与现有 Bearer API 并存的过渡方案。

## 决策

1. React/Vite 控制台放在本仓库 `web/`，生产构建由同一 FastAPI origin 提供；API 路径保持 `/v1/*`，不开放跨域 Query 读取。
2. `POST /v1/web/session` 只在登录时接收一次 `apmq1`。服务端验证后签发短时、host-only、HttpOnly、SameSite=Strict Cookie；生产强制 Secure。
3. 签名 payload 只包含 Query key ID、签发/过期时间和 CSRF digest，不包含 raw key、tenant/app/environment 或 L2 数据。签名使用独立 `APM_WEB_SESSION_HMAC_KEY_B64`。
4. 每次 Cookie 认证都从数据库重新验证 Query key/tenant active、role、撤销和到期状态，因此撤销即时生效；session expiry 不晚于 Query key expiry。
5. Cookie 驱动的 POST/DELETE 使用与签名 payload 绑定的 double-submit CSRF token。显式 Bearer 调用不是 ambient authority，继续兼容原 API 而不要求 CSRF。
6. 页面和 scoped API 禁止缓存；静态 HTML 有严格 CSP、frame deny、no-sniff 和 no-referrer，哈希 asset 可 immutable cache。
7. 首个页面只消费已冻结 Query/BFF；不会直接访问 PostgreSQL、ClickHouse 或 SigNoz，也不会在前端计算缺失状态或自动执行发布动作。

## 不采用的方案

- **把 `apmq1` 放 localStorage/sessionStorage**：长期 credential 可被同源 XSS、浏览器扩展或共享设备恢复。
- **把 key 放 URL/query string**：会进入历史、日志、referer 和截图。
- **直接暴露共享 SigNoz UI**：无法满足本产品的固定 tenant/app/environment 和 L2 审计边界。
- **现在自建用户名/密码数据库**：会新增密码重置、MFA、锁定、邮件与账号生命周期，且未来仍要迁移企业身份。
- **另建跨域静态站点**：增加 CORS、Cookie domain、CSRF 和部署复杂度，对当前单仓服务端没有收益。
- **把 Query key 或 scope 全部封进长期 JWT**：撤销、role/scope 变更不能即时生效，容易形成第二份授权真值。

## 后果

- 本地 loopback 和下午购买服务器后的同源 HTTPS 可以使用同一构建，不需重写登录或 API 客户端。
- Web session signing key 必须独立生成、保管和轮换；轮换会主动结束现有 Web 会话。
- 当前仍是 Query Key bootstrap，不是最终 SSO。未来接入 OIDC 时保留 HttpOnly same-origin session 和 fixed-scope BFF，把登录交换替换为 OIDC code flow即可。
- 同源只能降低而不能消除 XSS 风险；CSP、依赖锁、无 inline script、raw no-store 和代码审查继续是强制门禁。

## 验收

- 登录响应、Cookie payload、静态产物、localStorage/sessionStorage、审计和日志都不存在 raw `apmq1`。
- Session Cookie 为 HttpOnly/SameSite；生产缺 Secure 或弱 signing key 时配置 fail closed。
- Query key 撤销后已有 Cookie 立即失败；篡改、过期和非规范 Base64URL token失败。
- Cookie POST 缺失/错误 CSRF 被拒绝；Bearer API 保持兼容。
- viewer 无 L1/L2/decision 权限；investigator raw 仍要求 purpose/reason 且审计先 commit。
- 网页和 API 响应为 no-store，HTML CSP 与静态 asset cache 头可自动化复核。
