# ADR 0011：运行会话统计与多信号导出

日期：2026-10-14。状态：服务端已实现，客户端扩展待接入（2026-11-02 核对）。补充 ADR 0006/0010。

## 决策

V3 occurrence 追加 optional `session_id=7`、`device_model=8`、`os_version=9`。既有 field numbers、schema/batch ACK 和 V1/V2/V3 解码保持兼容。客户端后续需实现 durable codec V5 并继续读取 V1–V4；当前仍是 V4。旧缓存和历史 app_exit 不补当前进程身份。

session_id 是一次 SDK 运行期的匿名 UUID，成功初始化后固定，重复 init 不改变，stop 后新 init 新建。不是用户、foreground 或业务 session。设备标签固定源于标准 Build 资源，最多 256 UTF-8 bytes；不得从 extras、URL 或自定义 tag 推断。

SDK 待实现：每次运行期发出精确 `core/session_start`，fields 为整数 `session_schema_version=1`、`session_count=1`，CRITICAL 同步 durable handoff，避开 sampling/aggregation 和子进程异步入口。SDK disabled 不发，失败记录诊断。事件有标准 occurrence；不能用其他事件替代 start。

服务端 migration `20261014_0009` 增加 session HMAC/质量/key version、device/OS 及每信号 export progress。session 使用 `androidapm.session.v1` 独立 HMAC domain；已知 installation/session 明文在持久化、投影、符号任务前递归移除。重放使用原 key version；旧 V3 新字段 absent 时从 canonical JSON 排除，payload hash 不变。

会话率的分母是当前 release/window 内有效 start 的不同 HMAC 会话。Crash-free 的失败集合仅 Java/Native 现场事故，ANR-free 仅 exact ANR；重复现场事件只影响一次会话。Tombstone 与 app_exit 是历史证据，不加入现场分子。缺身份、未见窗口内 start、HMAC 轮换、SDK health/丢弃/迟到/最低安装门槛不满足均保留空值及原因；不得把缺失当真实零值。

Normalization v4 统一已审查的 [统计目录](../12-统计契约与口径.md)，固定类别严格 allowlist，原始未知值仅保留在 L2。Native/tombstone 具有不同 family 和指纹；relative PC/build identity 参与分组，load_bias 不参与。既有 Java/symbolized fingerprints 和 aliases 不改写；仅为仍保留 raw 且未有指纹的历史 Native 行补指纹。过期原始证据不重新推导。

Trace 仅支持客户端手动 span，默认 exact module `trace`。`spanSchemaVersion=2` 的真实 start/end epoch 与单调 duration 独立保存；旧 span 缺起止保持 `TIMING_UNAVAILABLE`，不以 event.timestamp-duration 还原。自由 name 仅 L1/L2；OTLP name/body 固定 `manual_span`，任意 attr_* 不进默认索引。不是自动网络 service graph。

OTLP Metrics/Traces 分别显式 opt-in，默认关闭；numeric observation 作为 Gauge，窗口摘要与累计快照不伪造 Counter/Histogram。Logs/Metrics/Traces 的计划在第一次 claim 固定并持久化；每信号成功独立写回，全部 done/not-applicable 才全局 delivered。配置关闭不丢弃既定未完成信号；已 delivered 不自动重发。每次 signal 前用数据库时钟/owner/lease fence，失败遵循共同有界预算；OTLP partial_success 有 rejected 数时属于明确失败。

## 验证边界

SQLite migration、API、Web 和 mocked OTLP 验证服务端契约；SDK 尚未实现 optional session/device/OS/session_start/span v2，不把服务端 fixture 当作 SDK 验收。没有生产 PostgreSQL/SigNoz/TLS/通知环境，没有真机运行结果。参考 [OTLP 规范](https://opentelemetry.io/docs/specs/otlp/) 与 [Metrics 数据模型](https://opentelemetry.io/docs/specs/otel/metrics/data-model/)。
