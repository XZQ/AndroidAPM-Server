# 统计契约与口径

2026-11-02 来源补充：目录包含服务端预留的 core/session_start，当前 Android SDK 尚未发出此事件，也未提供 optional session/device/OS 或 span v2 起止；客户端 durable codec 仍为 V4。服务端接受扩展输入并验证质量，旧 SDK 的会话率/设备覆盖保持不可用。OTLP SDK-health 每字段每事件只输出一个点；stage count 缺失或非正时不导出占位延迟零。

2026-10-14 实现以客户端 main source 和 Collector 持久化事实为准。性能页现在覆盖 **15 个监控域及 core 的 66 种固定事件、243 个数值契约、29 个固定类别契约**。目录定义在 `src/androidapm_server/performance_catalog.py`；分布、固定类别及加权 FPS 实现在 `src/androidapm_server/performance.py`。操作入口见 [本地产品功能](11-本地产品功能.md)。

本页目录中的 `core/session_start` 是标准 telemetry 会话开始信号，专门的会话健康统计使用 occurrence-bound session 身份；性能页只计该事件，不从 session event 数推断健康率。`core/sdk_health` 是实际周期运行时身份，测试/helper 的 `sdk_self_monitor/sdk_health_report` 不在目录中。

## 固定事件覆盖

以下所有 exact `module/name` 均有事件计数。对每个事件分别返回当前版本计数、基线版本计数、命中查询的合计和未绑定发生时版本的计数；没有数值字段的事件也不会遗漏。Java、Native、历史 tombstone 和历史 app_exit 是独立事件，不相加伪装为唯一事故数。

| module | exact name |
| --- | --- |
| crash | `java_crash`、`native_crash`、`tombstone_crash`、`app_exit` |
| anr | `anr_detected` |
| launch | `cold_start`、`warm_start`、`hot_start`、`first_frame_rendered`、`launch_bottleneck` |
| fps | `fps_stats` |
| render | `frame_metrics`、`view_count_spike`、`deep_hierarchy` |
| network | `network_request`、`network_error`、`network_aggregate`、`network_phase` |
| memory | `memory_snapshot`、`memory_alert`、`memory_leak`、`oom_warn`、`oom_critical`、`system_low_memory`、`system_mem_warn`、`native_heap_warn`、`hprof_dump`、`native_heap_stats` |
| slow_method | `slow_method_detected`、`slow_method_instrumented`、`hot_methods_detected` |
| io | `io_issue`、`io_main_thread`、`io_small_buffer`、`io_duplicate_read`、`io_fd_leak`、`io_closeable_leak`、`io_zero_copy_opportunity`、`io_throughput` |
| sqlite | `slow_query`、`main_thread_db`、`large_db_operation`、`query_plan_issue` |

| core | `sdk_health`、`session_start` |

计数为 0 只表示该查询没有收到该类事件，不能证明模块启用、宿主接线、无采样或真实总体没有异常。目录以固定值渲染；未知或任意自定义 event name 不成为新的 L0 类别。查询继续由凭据绑定 tenant/app/environment，版本过滤及时间窗口下推 SQL，超过原始观测预算拒绝整个查询，不给部分结果。

每个指标返回 mean/minimum/maximum/P50/P75/P95、有效样本、匹配事件分母、覆盖率，以及 missing/invalid/unavailable 数量。每条匹配事件是一份观测，分位数采用线性插值；只纳入 `OCCURRENCE_BOUND` 版本，不把 V2 batch declaration 当发生时版本。无匹配事件为 `NO_DATA`；字段全不可用时为 `UNAVAILABLE`；全有真实有效 0 才是 `ZERO`；部分有效为 `DEGRADED`。

86 个真实整数计数、帧/对象/层级契约使用 integer 转换，拒绝布尔和分数计数；其余 157 个是 number，包括平均 buffer 数、内存、频率/比例/速率和兼容耗时。非有限值及物理负值无效。`heapGrowth` 是前后 Heap 使用率之差，合法范围 -1..1；`cpuPercent` 实际单位为 cores，1.0 代表占满一个核，可大于 1，不能当作 0..100 百分比或上限 1 的普通比例。

## 固定类别

29 个类别契约只接受源码规定的固定枚举或布尔值：

- FPS `dropSeverity` 为整数 0/1/2/3。
- IO/SQLite/Binder `isMainThread`，IO `operation/opType` 与 `hookLevel`。
- SQLite 查询计划 `SCAN_TABLE/USE_TEMP_BTREE/AUTOINDEX`。
- WebView `script/stylesheet/image/xhr/other`、Bridge 方向及 success。
- 慢方法 isSevere、内存 ACTIVITY/FRAGMENT/VIEW_MODEL/CUSTOM 泄漏类型、isLowMemory。
- GC 的三个 availability 标记、启动瓶颈阶段及 isColdStart。

每个类别返回固定值计数、匹配事件数、可用数和 missing/invalid/unknown/expired 数。原文清理会删除字符串类别证据；此前有效的类别改为 `EXPIRED` 并单独返回 `expiredCount`，不当作未知新枚举，也不继续计入原固定值。布尔和整数类别仍按保留的数值事实统计。没有认识的类别时保留状态；新枚举先为 `UNKNOWN`，不把原值加入 registered/indexed attributes。false 是有效布尔观测，缺字段不是 false。原始 URL、SQL、路径、堆栈、JS、任意场景/用户 tag、线程/方法/Bridge/池名均不构造 group-by。

## 加权和来源限制

- FPS 加权值为 `sum(fps * windowDurationMs) / sum(windowDurationMs)`，只使用同一事件中的有效 FPS 与正数窗口时长。没有窗口或窗口为 0 的观测被排除，并显示其数量与覆盖。只代表 SDK 发出的异常窗口，不能称全量帧率。实现用缩放权重避免合法有限数聚合溢出；累计窗口时长超出浮点范围时为 null，加权值仍可用。
- FPS 的 droppedFrames 与 render 的 droppedFrames 不是同一计数：后者是 FrameMetrics 回调丢弃数量。两域独立展示。
- GC false availability 下的 placeholder 0 是不可用。dispatcher stage count=0 时，其零延迟是空直方图占位，不参与延迟分布；有 count>0 的实际零延迟可以为 ZERO。各 stage 的 P95 字段是 SDK 直方图保守上界，其服务端分布仍是上报上界的分布。
- IO `io_throughput` 的 `totalReadBytes/totalWriteBytes/totalIoOps` 为累计快照，`throughputWindow` 是触发操作数，源码没有时间窗口。不能相加当增量，也不能构造 bytes/s。网络 `network_aggregate` 同样读取累计计数，失败比例只代表选中的累计快照；不能把不同快照总数当独立请求数量。
- WakeLock/GPS 的仍活跃事件可能多次报告同一个宿主 tag 的延长持有。tag 不参与统计，也没有稳定统一 incident ID，所以事件数不是唯一资源数，duration 不相加作为实际耗电量。
- `first_frame_rendered` 在客户端当前 Choreographer 回调上观测，发生在 draw 前，不能证明首帧已经呈现。旧目录误将 `phaseFirstFrameMs` 放在 cold_start，现移至实际发该字段的 first_frame_rendered；不存在的契约不补值。
- WebView SDK 只发 `resource_waterfall` 摘要，未发逐资源列表。页面完成时尚未获得精确结束回调的资源用页面完成时间作上界。这里只显示摘要分布及慢资源固定类型，不能伪造逐条瀑布或精确关键路径。
- Native Heap SDK 的 `nativeTotalAllocBytes/nativeTotalFreeBytes` 实际来源为 Debug 当前 allocated/free API，所以标签使用当前量；不宣称累计 malloc/free、峰值或分配次数。Native Heap 峰值/次数和 GPU overdraw 当前没有可用采集来源。
- HPROF 只计 dump 事件和文件大小，不公开设备本地文件路径或不存在的下载端点。泄漏对象类、SQL/方法名称等诊断证据只在权限受控事件详情读取。
- 部分 SDK 旧数据以 0 代替不可读系统字段，但没有 availability 标记，服务端不能恢复丢失的语义。展示是 SDK 已报告的数值，不能据此证明系统计数能力或总体覆盖；新协议/采集标记应先落客户端，再扩统计口径。

## 验证入口

`tests/test_performance_completeness.py` 覆盖配对 FPS 加权与缺失/非法窗口、巨大有限值、count-only 事件、不同 crash 事件、固定类别隐私与未知、真实 raw prune 后类别过期与未知/无效/缺失区分、GC availability、多核 CPU、真实扩展字段、分数计数以及空 stage 直方图。完整仓库运行结果以 [PROJECT_HANDOFF](PROJECT_HANDOFF.md) 最新条目为准；本页不将本地测试推断为 PostgreSQL、真机或 SigNoz 生产验收。
