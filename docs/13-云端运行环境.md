本机（Windows 工作机）**没有 SSH 私钥、云 API 凭据、Docker CLI、tccli 或腾讯云 CVM 类连接器**，因此以上均为公网侧证据；容器内配置、数据库内容、账单和主机安全事件不能从本机验证。可用通道是云控制台 OrcaTerm / VNC / 自动化助手（命令按地域隔离，需切到首尔）。

**重要区分**：运行时 `APM_ENVIRONMENT` 与 Query Key 的数据 `environment` scope 是两个不同概念。线上 `/docs` 返回 404，按 `src/androidapm_server/main.py` 的条件说明运行时为 `production`；历史记录里的 `staging` 描述的是凭据的数据 scope，不能据此推断运行时未启用生产校验。

## 2. 部署形态与仓库的差异（需服务器侧核对）

2026-11-05 的容器日志证据显示，云端不是仓库 `compose.yaml` 的直接副本：

- 对外服务容器为 `androidapm-public-trial-gateway`，端口绑定 `127.0.0.1:8081 -> 8080`；另有几乎无流量的 `androidapm-server-gateway-1` 残留，**未擅自停用**。其余为 `androidapm-server-{postgres,worker,alerts}-1`。
- 内存上限是云端额外 override（gateway 384 MiB / 512 MiB、postgres 512 MiB、worker / alerts 256 MiB），仓库 `compose.yaml` 与 `compose.production.yaml` 都没有 `mem_limit`。
- 2026-11-07 实测 `GET /` **没有** `Strict-Transport-Security`，且仍带 `Server: uvicorn`；仓库 `deploy/caddy/Caddyfile` 配置了 HSTS 与 `-Server`。同时 `main.py` 只关闭 `docs_url`、未关闭 `openapi_url`，但线上 `/openapi.json` 也是 404。
- 结论：线上 Caddy / 构建产物 / 环境变量与仓库资产存在差异。**不能仅凭这些差异断言线上跑的是旧版本**；必须先取回服务器实际配置再比对。

## 3. 运行时能力现状

仓库默认值（未在服务器核实，以下为**代码事实**而非线上结论）：

| 能力 | 默认值 | 位置 |
|---|---|---|
| 符号化 | `false` | `config.py` `symbolization_enabled`；`compose.production.yaml` 把 symbolizer 放进 `symbolization` profile |
| OTLP Metrics / Traces | `false`（opt-in） | `config.py` `otlp_metrics_enabled` / `otlp_traces_enabled` |
| OTLP Logs 导出 | `true` | `config.py` `export_enabled` |
| SigNoz 接收端 | 仓库不含 SigNoz / ClickHouse，端点须外部提供 | `compose.yaml`、`deploy/signoz/README.md` |
| SigNoz 告警模板 | `channels: []`、`production_ready: "false"` | `deploy/signoz/alerts/*.json` |
| SDK 输入 | Android SDK 仍为 durable V4，未上报标准 session/device/OS / span v2 | 见 `docs/02`、`docs/12`、`ADR 0011` |

**风险**：若云端 `export_enabled=true` 而外部 OTLP 端点不可达，事件会持续堆积到 dead letter 并占用 60 GB 单盘；容量准入只限制 inbox 行数与 raw 字节，不检查磁盘余量。必须核对云端 `APM_EXPORT_ENABLED`、OTLP 端点可达性、dead letter 数量与磁盘水位。

## 4. P0 待办（服务器侧，本机无法完成）

1. **证书续期监控**：当前是约 6 天有效期的短期证书，80 端口关闭，续期只能走 TLS-ALPN-01(443) 或 dns-01；443 被防火墙阻断会直接导致续期失败且缓冲极短。可用 `scripts/check_tls_expiry.py --host <公网入口> --min-days 3` 做外部巡检，并把它接入定时告警；建议绑定域名，避免依赖签给 IP 的证书。
2. **处理主机安全事件**：控制台显示主机安全「防护中」但状态为「风险」，2026-11-04 记录 31 个待处理事件，11-07 仍未处理。
3. **回收部署配置**：按第 5 节清单取回实际 compose / Caddyfile / 环境变量 / 容器清单，纳入版本管理（脱敏）后再判断是否需要清理空跑 gateway、补齐 HSTS 与资源限制。
4. **确认外部 OTLP 接收端**：SigNoz / Collector 是否在跑、导出是否成功、dead letter 是否堆积。
5. **备份与恢复**：仓库目前没有 `pg_dump` / PITR 实现；按 `docs/08-部署与运维.md`「备份与恢复演练清单」执行并留存证据前，不得把"已部署"写成"可恢复"。

## 5. 部署配置回收清单（只读，在服务器上执行）

```bash
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}'
docker inspect <gateway容器> --format '{{json .Config.Cmd}} {{json .Config.Env}}'   # 输出含密钥，勿直接贴回仓库
docker compose -f <实际 compose 路径> config                                        # 同样含密钥，先脱敏
cat <实际 Caddyfile 路径>
certbot certificates 2>/dev/null || true                                             # 确认续期方式
df -h / && du -sh /var/lib/docker 2>/dev/null || true
```

环境变量回传时只保留**键名与是否配置**，不要带值。核对项：`APM_ENVIRONMENT`、`APM_EXPORT_ENABLED`、`APM_OTLP_*_ENDPOINT`、`APM_SYMBOLIZATION_ENABLED`、`APM_INBOX_MAX_*`、`APM_WEB_SESSION_COOKIE_SECURE`、容器内存上限来源。
