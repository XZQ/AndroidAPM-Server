# 安全、隐私与租户模型

## 信任边界

APK 和网络请求均不可信。tenant 身份只能来自服务端验证过的凭据；`appId`、environment、版本、installationId 和事件 fields 都是需要校验的声明。SigNoz/ClickHouse 不直接暴露给移动端。

## 凭据模型

- 初始接入使用随机 256-bit ingest key，显示一次；数据库只保存带版本的 Argon2id 哈希、key id、tenant、app/environment scope、状态和到期时间。
- 每次认证采用常量时间验证；缓存按短 TTL 保存解析后的 scope，不缓存原始密钥到日志或指标标签。
- 轮换允许新旧 key 短暂重叠，撤销立即使缓存失效并记录 actor/reason/request ID。
- 生产目标是客户端 `AuthProvider/HeaderProvider` 获取短期 Token；长期管理凭据绝不进入 APK。
- 管理 API 与 ingest API 使用不同凭据、受众和网络入口。

## 租户隔离

- 所有业务表以 `tenant_id` 为第一隔离维度；查询 repository 强制注入 tenant context。
- 生产启用 PostgreSQL Row Level Security 作为纵深防御，并用跨租户负向测试验证。
- 唯一约束使用 `(tenant_id,event_id)`；凭据 scope 再限制 app/environment。
- SigNoz Community 自托管不能被假定提供本产品所需的强多租户 RBAC。第一阶段每个信任域/环境使用独立 SigNoz 实例或仅通过受控后端查询；不能把共享 SigNoz UI 直接开放给互不信任的客户。

## 数据最小化与 PII

- SDK 默认脱敏仍需改为生产安全配置；服务端再做字段 allowlist/denylist、URL query、SQL literal、header、token、email/phone 等规则清洗。
- `installationId` 使用不可逆租户盐 HMAC 后再进入分析维度；不收集 Android advertising ID、IMEI、手机号等硬标识。
- 原始 payload 只在受控 inbox 保留，结构化日志不得打印它。
- 高风险字段被拒绝或置换时记录规则 ID 和计数，不记录原值。
- 提供 tenant/app/匿名主体维度的导出与删除任务，并覆盖 ClickHouse、PostgreSQL、对象存储和缓存。

## 网络与平台安全

- 外部只开放 TLS 1.2+ 的 443；数据库、SigNoz OTLP 和管理面位于私网。
- 反向代理限制 body、连接、header、超时和源速率；应用层再次校验。
- 容器非 root、只读根文件系统、最小 Linux capabilities、固定镜像 digest、SBOM 和漏洞扫描。
- 密钥来自部署平台 secret manager；`.env` 只用于本地示例且不提交真实值。
- PostgreSQL 传输加密、磁盘/备份加密、最小角色；Gateway 无 DDL 权限，迁移使用独立角色。

## 审计与响应

审计至少覆盖：密钥创建/轮换/撤销、scope 修改、配置发布/回滚、符号上传/删除、人工重放、数据导出/删除、管理员查询和保留策略变更。审计记录包含 actor、tenant、动作、对象、结果、时间、request ID 和来源，不包含 secret。

发现密钥泄漏时：立即撤销、停止对应 scope、查询异常 ingest、生成替换 key、通知应用发布/动态刷新、记录事件复盘。发现跨租户风险时直接阻断发布并假设数据已暴露，启动取证和通知流程。
