# 测试与验收

## 测试金字塔

### 单元与属性测试

- Line Protocol 兼容 parser、Protobuf frame parser、Gzip 有界解压。
- 枚举、UTF-8、时间、map/字段/事件/批次限制。
- 认证 scope、constant-time key verifier、PII 规则。
- OTLP 映射快照、数值注册表和错误降级。
- 重试、退避、lease owner、过期重领和状态机。
- Hypothesis/fuzz corpus 覆盖截断、随机长度、压缩炸弹和未知字段。

### PostgreSQL 集成测试

- 同 batch 内重复、历史重复、两个连接并发插入相同 eventId。
- 整批原子性：第 N 条失败时零插入。
- worker `SKIP LOCKED` 不重复认领；非 owner 不能完成；lease 到期可重领。
- RLS/tenant repository 的跨租户负向测试。
- 迁移从空库、前一版本升级、回滚边界和索引计划。

### 契约与端到端

- 使用 Android 客户端生成的真实 Line/Protobuf/Gzip fixture，不手写替代。
- 真实 `HttpApmUploader` 指向 Gateway：2xx 后客户端 ACK；故意丢 ACK 后重传只形成一条事实。
- OTLP mock 验证 wire bytes；SigNoz staging 验证日志/指标可查询。
- Dashboard 合成数据验证过滤器、单位、空数据、告警触发/恢复。
- mapping/Native fixture 验证正确、错误和缺失 build-id。
- CI key 与 ingest key 不可互换；上传体上限、SHA-256、mapping UTF-8/结构、ELF ABI/.symtab/build-id、identity checksum 冲突。
- 符号任务 metadata_missing/symbols_missing/requeue、owner-only 完成、retry/exhaustion、raw export 释放和稳定指纹。
- 客户端实际周期事件 `core/sdk_health` 与 SigNoz 资产查询完全一致；helper/test-only `sdk_health_report` 不得冒充运行时 fixture。
- Crash 查询使用 exact event set；普通 `app_exit`、异常 `app_exit`、`java_crash` 和 `anr_detected` 的计数/关联规则分别断言。
- URL/SQL/path/stack/message/JS/custom context 不会绕过字段 allow-list 变成默认高基数属性。
- 旧版本事件写入 durable outbox、升级应用后再上传：V3 occurrence snapshot 仍归旧版本；V2 batch resource 只能标为 `BATCH_DECLARED` 并被生产版本比率/符号化排除。
- installation 入库前生成 tenant-scoped HMAC/key version，`payload_json`、结构化日志、OTLP、Dashboard 导出和通知均扫描不到明文；两个 tenant 的相同输入不会得到相同分析标识。
- viewer 无法读取 raw URL/SQL/path/stack/JS/context，investigator 只能在自己的 tenant/app/environment 和受限窗口读取；L2 查看、导出和 break-glass 均产生不含原文的审计。
- Web 登录响应、Cookie payload、静态产物、localStorage/sessionStorage、审计和结构化日志不含 raw `apmq1`；session 篡改/到期/key 撤销失败，Cookie 写操作缺 CSRF 失败，显式 Bearer API 保持兼容。
- Web lint/typecheck/Vitest/build 全绿；浏览器验证 loading、partial error、`ZERO` 与 unavailable、窄屏、200% 文本、键盘焦点、主题和长 raw 内容。HTML CSP/no-store 与 hashed asset immutable cache 自动化断言。

2026-08-28 的本机闭环扩展为真实 V2/V3：JDK 17 编译并运行实际 `HttpApmUploader`，通过 loopback HTTP/Gzip 向运行中的 FastAPI/uvicorn Gateway 分别发送并重放两个 2-event batch；客户端验证精确 schema/batch/count ACK，迁移到 head 的测试用 SQLite inbox 最终只有 4 个唯一 eventId。脚本独立核对 V2 typed scalar、V3 occurrence release/build/variant、native frame、tenant-scoped HMAC/key version、明文删除和低质量请求声明不覆盖 occurrence。该证据验证跨语言 wire/本地持久化兼容性，不替代 PostgreSQL 并发/事务、TLS ingress、代理丢 ACK、真实 SigNoz 或生产部署验收。复现命令在 Android 客户端仓库执行：

```powershell
python tools/verify_collector_e2e.py `
  --server-repo D:\path\to\AndroidAPM-Server
```

## 首个产品垂直切片验收

首个发布门禁场景是“新版本 Java Crash/ANR 可信闭环”，不是单纯证明事件能进入 SigNoz。测试数据由真实 Android serializer/uploader 生成并固定 source revision/hash；套件覆盖 V3 occurrence、V2 和 legacy，至少覆盖：

1. 稳定版本与新版本、多个 installation 的周期 `core/sdk_health`。
2. `crash/java_crash`、`anr/anr_detected`、普通 `app_exit`、`app_exit:CRASH|ANR`、raw-only native/tombstone。
3. 相同 batch 重放、ACK 丢失、迟到、乱序和一个 eventId 内容冲突。
4. V3 occurrence 完整/缺失/冲突、V2 resource 完整、legacy installation 缺失、legacy 字段字符串化、symbol metadata/artifact/tool 各种状态；V2/V3 必填身份缺失应整批拒绝。
5. 两个 tenant 使用相同 installation 明文，HMAC 结果必须隔离；明文不得出现在 OTLP、日志或 Dashboard 导出。
6. 旧版本 Crash 在 outbox 中跨一次应用升级后发送，验证 occurrence release/build 身份不被当前 uploader resource/Header 覆盖。

端到端断言：

- PostgreSQL 中 exact eventId 唯一，OTLP/查询聚合也只有一个逻辑事实。
- Java Crash 只统计 `java_crash`，ANR 只统计 `anr_detected`；普通 `app_exit` 不污染，异常退出证据不与现场事件直接相加。
- 事件数始终可见；installation 缺失数据只从安装分母排除并展示 exclusion/coverage，百分比在门禁不足时为 unavailable。
- `app_exit` 的发生时间取 `exitTimestamp`，tombstone collection-time 单列；received time 仍用于管线 SLO。
- raw/symbolized stack 并列，`disabled/metadata_missing/symbols_missing/symbolized/failed` 可复核且不覆盖 raw。
- Dashboard 的 `ZERO/NO_DATA/UNAVAILABLE/UNKNOWN_COVERAGE/DEGRADED/LATE/ERROR` 都有 fixture；查询失败不沿用旧数字伪装实时结果。
- Crash/ANR 告警验证最小样本、identity coverage、SDK drop/late gate、触发、分组、静默、恢复和通知重试。

在统一 telemetry session 契约上线前，任何 Crash-free/ANR-free session 断言都必须失败或返回显式 unavailable。没有标准 host integration evidence 时，也不得从 Network/SQLite/IPC/WebView/Battery/IO 零事件断言“已接线且健康”。

## 字段注册与契约漂移测试

- 从客户端 source-reviewed event fixture 生成 `(module,name,field,type)` 快照；新增/改名/单位变化必须显式更新注册表和相应文档。
- V2 typed scalar、legacy strict parse、非有限浮点、BigInteger/BigDecimal、null/invalid/unavailable 分支分别测试。
- raw 与 `<name>_aggregated` 不混算；聚合 count/window 和 scene/context 丢失必须成为可见 data form。
- 受控属性有 cardinality budget；使用随机 URL、SQL、path、stack、dynamic trace name/context 验证不会产生无界维度。
- resource/session/build/device 字段缺失时不注入空字符串或 0，不创建错误 Metric/Span。
- `AUTHENTICATED/OCCURRENCE_BOUND/BATCH_DECLARED/REQUEST_DECLARED/HOST_CONTEXT/ABSENT` 不可通过查询或迁移互相冒充；仅 occurrence-bound release identity 进入生产版本对比和精确符号化。

## 故障注入

- PostgreSQL 在 commit 前/后断连，确认不会错误 ACK。
- Gateway 处理完成但反向代理丢响应，确认客户端重放幂等。
- SigNoz/网络 429、5xx、超时、慢响应、永久 4xx。
- worker 杀进程、时钟偏差、lease 过期、重复 worker。
- 磁盘接近满、连接池耗尽、inbox 高水位、对象存储不可用。
- 密钥撤销缓存、轮换重叠、跨 tenant/app/env 尝试。

## 性能与长稳

初始基准场景：32 events/batch、1 KiB/event，分别测试纯 Line、Protobuf、Gzip。记录吞吐、ACK P50/P95/P99、CPU、RSS、数据库连接/IO/WAL、inbox 增长和 worker 可见延迟。结果必须注明硬件、并发、数据分布和命令。

发布前执行至少 2 小时稳态 + 峰值压测和 72 小时 soak。容量模型用实测而不是框架宣传；若单实例 Python Gateway 在目标硬件无法满足预算，先剖析解析/数据库瓶颈，再依据 ADR 触发 Go/Rust 数据面评估。

## 安全验收

- SAST、依赖/镜像漏洞、secret scan、SBOM、许可证清单。
- OWASP API 测试：认证绕过、对象/函数越权、资源消耗、注入、SSRF、错误信息泄漏。
- 跨租户读写是零容忍发布阻断。
- 日志扫描确认 Authorization、原始 key、未脱敏 body 不出现。
- 备份恢复与数据删除请求有真实演练证据。

## 发布门禁

P0：格式/静态检查、单元、PostgreSQL 集成、迁移、契约、镜像构建、secret scan 必须全绿。符号化发布还要求真实 R8 mapping 与每个 ABI 的未剥离 ELF/crash fixture，测试替身不能替代真实工具结果。P1：SigNoz staging E2E、告警、备份恢复、故障注入和性能预算必须在生产发布前完成。外部资源不可用时，状态写“待执行/被何物阻塞”，不得写“通过”。

Web 变更的 P0 命令为 `pnpm --dir web run lint/typecheck/test/build`；Docker 镜像必须从 lockfile 在独立 Node stage 构建同一份 `web/dist`，不能把开发服务器或 `node_modules` 放进 runtime。生产 session 配置还要验证 HTTPS Secure Cookie、独立 HMAC key、撤销和 CSRF。
